# MEDREV — RACIOCÍNIO CLÍNICO: A FUNÇÃO DEFINITIVA

> Não é "mais um banco de casos". É um **ginásio de illness scripts** feito de micro-encontros rápidos focados nos **pontos críticos de decisão (key features)**, que tornam o raciocínio do aluno **visível** ao lado do raciocínio do expert, treinam **discriminação** entre diagnósticos confundíveis, e voltam **espaçados e variados** para virar conhecimento durável. Rápido, no celular, em toques. Desenhado para mudar o raciocínio — não só registrar acertos.

---

## 1. A ideia central (o que muda tudo)

Três decisões de design carregam o produto inteiro:

1. **A unidade não é o caso — é o illness script.** O caso é descartável; o que fica na cabeça do aluno é o esquema completo: predisponentes → mecanismo → quadro cardinal → diferenciais obrigatórios → workup → conduta → red flags + as pistas que discriminam. A função **constrói e amadurece scripts inteiros**, e mede maestria **por compartimento do script** (reaproveitando o BKT/PFA que já existe).

2. **Duas camadas, nesta ordem — primeiro fixar o script inteiro, depois aplicar.**
   - **Camada 1 — Fixar o script (active recall do norteador completo).** O aluno reconstrói de memória **todo** o illness script da doença base, encaixando em compartimentos fixos, e confere contra o canônico. É aqui que o esquema **inteiro** entra na memória de longo prazo — não um pedaço. Espaçado pelo FSRS; compartimento fraco volta antes.
   - **Camada 2 — Aplicar o script (key feature + contraste).** Só **depois** que o script existe na cabeça, os micro-encontros rápidos (2–4 min) exercitam **usar** o script no passo crítico de decisão e discriminar do confundível. O *key feature* é o foco da **aplicação** — não o método de fixação. Sem a Camada 1, o key feature treina decisão sobre um script que o aluno não tem; sem a Camada 2, o script fixado vira lista decorada e inerte.

3. **O momento mágico é tornar o raciocínio visível.** No reveal, o raciocínio do aluno aparece **lado a lado** com o do expert, com a **divergência destacada** e nomeada (ancoragem, fechamento precoce, negativo pertinente ignorado). O que muda conhecimento não é o placar — é **ver onde seu pensamento desviou**.

Tudo o mais (calibração, geração, discriminação, espaçamento) serve a essas três. **Correção em relação à versão anterior:** o key feature é um construto de *avaliação* (amostrar muitos casos com eficiência), não o método de *codificação* do esquema. Para o médico internalizar tudo que é norteador de uma doença, a fundação é o active recall do script **completo** (Camada 1); a Camada 2 torna esse script utilizável.

## 2. Por que isso muda o conhecimento (ciência → design)

| Decisão de design | Evidência | Por quê |
|---|---|---|
| Focar em **key features** (passos críticos), não H&P completo | Page & Bordage — Key Feature Problems: validade/confiabilidade com casos curtos; mais casos no mesmo tempo | Rápido + amostragem ampla + foca onde o erro mora |
| **Pontuar a justificativa** (apoia / fala contra / esperado-mas-ausente), não só o diagnóstico | DxJ é o maior déficit e preditor; negativos pertinentes subutilizados | Treina o que prediz competência e o que a banca cobra |
| **Reflexão estruturada** (listar a favor, contra, e o que faltou) | Mamede & Schmidt — deliberate/structured reflection aumenta acurácia | Força o Sistema 2 a verificar a intuição |
| **Discriminação** entre confundíveis (modo contraste) | Brunmair & Richter (interleaving de confundíveis); CBCR (comparar scripts) | Discriminar é a habilidade do expert, não recordar mais fatos |
| **Gerar** a resposta (write-in) antes de revelar | KFP favorece write-in; efeito de geração; retrieval practice | Produzir > reconhecer para transferência |
| **Commit + confiança** antes do reveal | Calibração diagnóstica; overconfidence → erro (Berner & Graber) | Treina metacognição (saber o que não sabe) |
| **Dois passos**: gestalt (S1) → verificação (S2) | Dual-process; estrutura do raciocínio do expert | Captura a intuição e depois a corrige |
| **Tornar o raciocínio visível** (seu vs expert) | Cognitive apprenticeship; self-explanation | O gap nomeado é o que reorganiza o esquema |
| **Reexposição espaçada e variada** (mesmo script, vinheta nova) | Spacing + variabilidade → transferência | Script "sabido" testado em apresentação atípica = durabilidade |
| **Andaime que desvanece** (cued → independente) | Faded examples vs cued reflection | Dificuldade desejável calibrada ao nível |
| **Seleção personalizada** (script fraco × incidência × seu erro) | Mastery learning; deliberate practice dirigida ao gap | Sempre treina o buraco real, não o que você já sabe |

## 3. A experiência (rápida, em toques, uma decisão por tela)

O aluno abre e recebe **o próximo passo** já escolhido pelo sistema. Não escolhe caso, não configura nada. A função tem **uma fundação (Drill 0) e três drills de aplicação**. Um script novo (ou fraco) começa sempre pela fundação; scripts já fixados vão direto à aplicação.

### Drill 0 — "Fixar o Script" (active recall do norteador completo) · ~3–4 min · FUNDAÇÃO
O objetivo é o aluno guardar **a doença base inteira**, não um pedaço.
1. Gatilho: nome da doença (ou uma vinheta-âncora típica).
2. **Despejo livre** (~60s): "escreva tudo que sabe sobre esta doença" (recall gerativo, sem estrutura).
3. **Mapeamento em compartimentos** (o esqueleto do illness script), preenchidos de memória:
   - Predisponentes / epidemiologia · Mecanismo (fisiopato) · Quadro cardinal · Diferenciais que **não pode perder** · Workup-chave · Conduta de 1ª linha · Red flags.
4. **Confere contra o script canônico** e **autoavalia por compartimento** (verde/amarelo/vermelho).
5. **Duas direções:** alterna entre doença→achados e **achado→doença** ("que padrão isto sugere?"), porque a prova cobra padrão→diagnóstico.
6. Cada **compartimento fraco** vira item espaçado próprio (volta antes pelo FSRS) — e o aluno é levado **imediatamente** a um Drill A/B sobre o mesmo script, para usar o que acabou de recordar.

→ É aqui que o esquema **completo** entra na memória. Sem inerte: termina aplicando. Andaime desvanece (compartimentos rotulados no começo → vazios depois).

### Drill A — "Primeira Impressão" (gestalt + calibração) · ~90s · APLICAÇÃO
1. Vinheta curta (3–4 linhas).
2. **Toque** sua hipótese principal (chips) + um slider de **confiança**.
3. **Uma** pergunta de key feature ("qual o próximo passo que confirma/afasta?").
4. Reveal + **feedback de calibração** ("você estava 90% confiante e a pista te contradizia").

→ Treina reconhecimento de padrão e calibração. É o aquecimento.

### Drill B — "Defenda o Diagnóstico" (o coração) · ~3 min
1. Vinheta.
2. **Escreva** o diagnóstico líder (write-in curto) + 1–2 alternativos.
3. **Reflexão estruturada em 3 colunas** (toque/escreva):
   - O que **APOIA** o líder
   - O que **FALA CONTRA** (negativos pertinentes)
   - O que eu **esperaria e não vi**
4. Commit final + 1 frase de autoexplicação.
5. **Reveal lado a lado** (seu raciocínio | do expert) com divergência destacada → **scorecard de justificativa** (não binário): apoio, negativos pertinentes, adequação do workup, **penalidade por erro cognitivo**.

→ Treina e mede a justificativa — o déficit que prediz competência.

### Drill C — "Separe os Gêmeos" (discriminação) · ~2 min
1. 2–3 vinhetas **confundíveis** lado a lado (mesma queixa, diagnósticos diferentes — vindas dos `confusableSets`).
2. Para cada uma: **toque a única pista que a discrimina**.
3. Reveal: a tabela de discriminação do expert (a feature que separa cada par).

→ Treina a habilidade central do expert: discriminar rápido entre parecidos.

*(Mantém o SCT — "Conduta sob Incerteza" — como quarto drill opcional; já é baseado em evidência.)*

### O reveal — o momento que muda conhecimento
Sempre o mesmo padrão visual: **duas colunas, seu raciocínio à esquerda, o do expert à direita**, com as divergências em destaque e **nomeadas** ("você ancorou na primeira hipótese", "ignorou um negativo pertinente: ausência de X afasta Y"). Abaixo, **um** próximo passo: virou card (se foi lacuna de fato) ou um caso de contraste (se foi raciocínio). Nunca um muro de texto.

### Crescimento visível (não streak)
O progresso é mostrado como **scripts amadurecendo** (ex.: "Dor torácica: 4/7 scripts maduros") e **erros que sumiram** ("você parou de ancorar em TEP"). Frame de competência (SDT), comparação a você mesmo — sem streak coercitivo.

## 5. O modelo de dados — script como entidade de 1ª classe

Hoje o "caso" carrega tudo. Inverter: **o illness script é a entidade**, e o caso é uma **instância** (uma vinheta que apresenta o script, típica ou atípica).

```
IllnessScript {
  id, area, subtopic,           // liga ao BKT/mastery por subtópico
  enabling, fault, consequences, management,
  keyFeatures: [ {prompt, expectedAction, isCritical} ],   // os passos que decidem o caso
  discriminators: [ {vs: scriptId, feature} ],             // o que separa dos confundíveis
  pertinentNegatives: [ ... ],                             // o que, ausente, afasta
  commonErrors: [ "anchoring", "premature_closure", ... ], // armadilhas típicas
}
CaseInstance {
  id, scriptId, vignette, presentation: "typical" | "atypical",
  keyFeatureAnswers, expertReasoningTrace
}
```

- **Maestria por compartimento do script** (BKT/PFA por subtópico → cada compartimento — predisponentes, mecanismo, quadro, diferenciais, workup, conduta, red flags — tem seu próprio sinal). Drill 0 e drills de aplicação alimentam `updateBayesianMastery`.
- **Roteamento Camada 1 → 2:** script com maestria baixa (ou novo) entra **sempre** pelo Drill 0 (fixar o script inteiro); script já fixado vai direto à aplicação (A/B/C). Compartimento vermelho volta antes.
- **Reexposição variada:** um script maduro reaparece numa `CaseInstance` `atypical` semanas depois (transferência). Agendado pelo **FSRS-Lite** sobre o *script* e seus *compartimentos* (não cria 2º scheduler).
- **Discriminação** vem de `discriminators` + `confusableSets` (bloco B7).

## 6. Personalização e agendamento (o que vem a seguir)

O próximo passo é função de:
```
prioridade(script) = (1 − maestriaBKT) × incidênciaENAMED × pesoDoSeuErro × dueFSRS
tipoDePasso: maestria muito baixa/novo → Drill 0 (fixar); senão → A/B/C (aplicar)
```
- **maestria baixa × incidência alta** → o gap que mais move a prova.
- **peso do seu erro:** se você ancora muito, mais Drill C (contraste); se ignora negativos, mais Drill B; se o buraco é o próprio esquema, **Drill 0**.
- **dueFSRS:** scripts e **compartimentos** "vencidos" voltam.
- Em fila vazia: **Drill C** (discriminação) sobre o set confundível mais fraco — interleaving de diferenciais.

O **andaime desvanece**: nos primeiros encontros de um script, o sistema mostra as colunas APOIA/CONTRA/FALTA já rotuladas (cued); conforme a maestria sobe, as colunas vêm vazias (independente) — dificuldade desejável calibrada.

---

## 7. Conteúdo: como escalar de 7 → muitos (sem perder qualidade)

O formato key feature torna cada caso **curto** → fácil de autorar e gerar.

- **Schema enxuto** por instância (vinheta + key features + traço de raciocínio do expert) — não um prontuário inteiro.
- **Geração assistida** a partir do script + subtópico ENAMED quente, **sempre com revisão humana** antes de publicar (ver §8, bloco RC-G).
- **Ordem de produção:** scripts dos subtópicos mais quentes primeiro; confundíveis em conjunto (alimenta o Drill C).
- **Meta:** múltiplas instâncias por script (típica + atípicas), ≥20 scripts por área quente.

### RC-AR — Drill 0 "Fixar o Script" (active recall do norteador completo) · *fundação*
**Objetivo:** o aluno reconstrói **todo** o illness script de memória, em compartimentos, e o sistema mede maestria **por compartimento**.
**Permitidos:** `components/RaciocinioClinico.jsx` (modo recall), `core/mastery.js` (maestria por compartimento), `core/illnessScript.js` (comparar recall × canônico).
**Proibidos:** 2º scheduler; texto livre sem estrutura no resultado (o despejo é etapa, mas a avaliação é por compartimento).
**Contrato:** fluxo §3 Drill 0 — despejo livre → mapear nos 7 compartimentos (predisponentes, mecanismo, quadro cardinal, diferenciais obrigatórios, workup, conduta, red flags) → conferir contra canônico → autoavaliar por compartimento → **2 direções** (doença→achados e achado→doença) → terminar levando a um Drill A/B do mesmo script. Cada compartimento vira item espaçado próprio.
**Segurança:** compartimento fraco volta antes (FSRS); andaime desvanece (rotulado → vazio); reusar FSRS-Lite.
**Aceite:** recall reconstrói os 7 compartimentos; autoavaliação por compartimento alimenta `updateBayesianMastery`; compartimento vermelho reaparece antes; termina em aplicação.
**Prompt:**
```
Adicione o Drill 0 "Fixar o Script" em RaciocinioClinico.jsx (modo recall). Fluxo:
1) despejo livre (textarea ~60s) "escreva tudo que sabe sobre <doença>";
2) mapear de memória nos 7 compartimentos do illness script (predisponentes, mecanismo, quadro cardinal,
   diferenciais obrigatórios, workup, conduta 1ª linha, red flags);
3) revelar o script canônico (illnessScript.js) e autoavaliar CADA compartimento (verde/amarelo/vermelho);
4) alternar 2 direções: doença->achados e achado->doença;
5) registrar maestria POR COMPARTIMENTO via updateBayesianMastery; compartimento fraco vira item espaçado (FSRS-Lite, sem 2º scheduler);
6) terminar levando o aluno a um Drill A/B do MESMO script (aplicar o que recordou).
Andaime: compartimentos rotulados no começo, vazios conforme a maestria sobe. Rode test+mojibake+build.
```

**Ordem:** RC-0 → **RC-AR (fixar o script — fundação)** → RC-1 → RC-2 (núcleo de aplicação) → RC-5 (maestria/espaçamento) → RC-3 → RC-4 → RC-6 → RC-G → RC-7. RC-AR + RC-1 + RC-2 já entregam o salto (fixar o script inteiro **e** aplicá-lo); o resto aprofunda.

## 9. Por que isto é "a melhor versão" — e não só melhor

- **Fixa a doença inteira** porque a fundação (Drill 0) é active recall do illness script **completo** — o aluno reconstrói todos os norteadores de memória, não um pedaço. Isso responde diretamente ao risco de "decorar só o ponto crítico".
- **Muda conhecimento** porque, sobre o script fixado, treina o que prediz competência (justificativa, discriminação, calibração) e torna o gap **visível e nomeado** — o mecanismo do aprendizado de expertise.
- **É durável** porque a unidade é o script (e cada compartimento dele), reexposto **variado e espaçado** (transferência), não o caso decorado.
- **É rápido e intuitivo** porque a aplicação é em toques (2–4 min), uma decisão por tela; a fundação é mais densa (3–4 min) mas só aparece quando o script é novo/fraco — o sistema dosa.
- **É pessoal** porque mira seu script (e compartimento) mais fraco e seu erro mais frequente.
- **Encaixa no organismo** que você já construiu: BKT por subtópico/compartimento, FSRS-Lite, taxonomia de erro, confusableSets, mentor que consome os motores. Nada de scheduler novo, nada de motor paralelo.
